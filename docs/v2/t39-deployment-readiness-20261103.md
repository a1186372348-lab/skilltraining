## 必须保留的时限问题

`after` 仍受路由或平台的最长运行时间约束，并非无限后台进程；官方当前文档列出 Fluid compute 下 Hobby 最大 300 秒。实际目标项目的计划和开关尚未核验。[Next.js after 文档](https://nextjs.org/docs/app/api-reference/functions/after)、[Vercel 函数时长文档](https://vercel.com/docs/functions/configuring-functions/duration)。

当前 `server/ai/client.ts` 默认单次超时 80 秒、最多重试 3 次，即一次客户端调用允许最多 4 次 HTTP 尝试。只计算这些请求的超时预算已达 320 秒，尚未加退避、外层评分重试和数据库耗时。由此可推断，**现有最长重试路径不能保证在配置的 300 秒内完成**；这不是一项已经复现的公网失败，也不意味着正常请求必然超时。T39 立项时的历史正常延迟不能证明当前所有重试路径适配。

发布前须验证正常路径和中断后的恢复路径，明确可接受的边界；不能悄悄降低用户已确定的思考配置、生成上限或重试规则，也不以“已有懒触发”承诺永久不会丢失或悬挂。本准备阶段不追加真实模型调用，不引入新云服务。

## 配置核对清单

这里只记录字段名称，不读取、复制或保存真实值。

- `DATABASE_URL`：目标云数据库及 schema；与开发库、测试库分别核对身份。运行测试绝不能使用该生产连接。
- `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`：服务端配置；最终真实训练需要单独明确模型调用范围和费用授权。
- `AUTH_SECRET`：稳定的生产会话签名密钥；生产代码缺失时应失败，不能依赖开发期临时值。
- `APP_BASE_URL`：实际公开 HTTPS 地址，核对邮件内回调和登录 cookie 行为。
- `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`SMTP_USER`、`SMTP_PASS`、`SMTP_FROM`：按已约定邮箱供应商配置；SMTP 授权值不入库、不入文档。Vercel 官方说明 Node.js 支持 SMTP，465 端口可用，但这一点不能代替具体邮箱连通性与投递验证。[官方 SMTP 说明](https://vercel.com/kb/guide/serverless-functions-and-smtp)。
- `TEST_DATABASE_URL`：只用于隔离测试，不把测试建库脚本作为云端生产发布步骤。

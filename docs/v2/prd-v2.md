## 1. 核心目标（Mission）

让训练从「闭环可用」走向「训练可信、训练成体系」：用户不仅每天能练，还看得见自己的成长阶段，信得过系统给的分数和方向。

## 2. 用户画像（Persona）

延续 V1：有产品认知但缺乏系统实战训练的初级产品经理、转岗 PM、承担产品职责的非正式 PM。V2 新增行为特征：已连续使用 1 周以上，开始产生更高阶诉求——**我这一阶段该主攻什么？我练了这么久真的进步了吗？**

## 3. V1 回顾（已交付，不再改动）

V1 已于 2026-10-07 完成全部 26 个任务包（T01~T26），训练闭环完整：注册登录 → 初始画像 → 今日训练（案例/资料/提示/追问）→ 评分 → 反馈 → 能力画像 → 训练历史 → 全局通知。V2 在其上叠加，不重构 V1 闭环。

## 4. V2 功能列表（按优先级）

### P0 地基
- **F1 题库扩容**：日常题 30~50 道（难度三层、领域覆盖矩阵、八维覆盖均衡）+ 基线题 16 道（八维各 2 道候选，难度基础层）；分三批生产评审，基线题在第一批。
- **F2 V1 小缺口修补 4 项**：新用户首登自动引导初始画像；基线会话在训练历史完整显示；画像页「下一步方向」改为基于真实弱项的动态结论；评分置信度展示。

### P1 信任根基
- **F3 总监 Agent 可度量调优体系**：每题配 1~2 份标准参考答案（AI 起草 + 人工评审修订）；评分回归集（prompt 变更前后对同一批评分，与人类基准对比一致性，过门槛才上线）；追问质量三查（针对用户答案/暴露真实盲点/不泄露 Rubric）；prompt 独立文件化 + 版本管理 + 回归报告留档。

### P2 核心升级
- **F7 基线测评升级（八维全覆盖）**：新用户画像后做八维基线测评——8 题起步（每题主测 1 个维度），系统对评分置信度低或表现异常的维度自动加深 1 题（最多 12 题）；支持分 2 次完成、断点续测；完成后一次点亮八维画像，跳过探索期直接进入强化期。

### P3 结构化训练（三形态串联：计划定方向 → 包是执行载体 → 路径是成长主线）
- **F5 周期训练计划**：每周一生成「本周主攻维度」（规则式：画像最低分维度），日常选题优先匹配；周日生成周回顾（完成天数、主攻维度有效分变化）；用户可拒绝，拒绝后本周不再重复推荐。
- **F4 专项训练包**：按弱项维度组织的 5 题系列（基础 2 → 进阶 2 → 挑战 1，逐题解锁），一次只进行一个包；完成输出包级诊断（有效分轨迹 + 下一阶段建议）；从画像页弱项节点一键发起。
- **F6 成长阶段与复测**：探索期→强化期→复测期产品化可见（含进入/离开条件）；某维度连续 3 次有效分 ≥75 触发换题复测（换题不换维度，验证是否真提升）；复测不占每日一题槽位。

### V3 及以后（本期不做，仅存档）
- 题型结构化（方案对比/指标设计等作答模板）
- 能力分数模型升级（近期权重/难度权重/衰减）
- 社区/排行榜/PK（继续排除）
- 能力测评扩容、移动端

## 5. 关键业务规则（V2 新增，BR-V2-1 ~ BR-V2-8）

- **BR-V2-1 选题优先级**：进行中的训练包 > 本周计划维度 > 待复测维度 > 纯自适应弱项。每层命中时「为什么是它」理由文案须明确来源。
- **BR-V2-2 计划与包打通**：周计划主攻维度生成后，系统可推荐/生成该维度训练包；用户可拒绝计划，拒绝后本周不再重复推荐同一维度。
- **BR-V2-3 单包进行制**：一次只进行一个训练包，完成或放弃后才能开新包；画像页其他弱项的发起入口显示禁用态并说明原因。
- **BR-V2-4 阶段判定**：存在未知维度=探索期；画像完整=强化期；某维度连续 3 次有效分 ≥75 触发该维度复测（复测为维度级状态，不影响其他维度正常训练）。
- **BR-V2-5 复测规则**：换题不换维度；复测题不占每日一题槽位；复测有效分 ≥60 为通过（维度标记已验证），<60 判定为题型熟悉假象，该维度重回主攻候选。复测启用前提：该维度可用未练题 ≥1 道（题库保障见 BR-V2-8）。
- **BR-V2-6 基线测评规则**：8 题起步每题主测 1 维；评分 confidence < 阈值（初定 70，回归集标定）的维度自动加深 1 题，上限 12 题；支持分 2 次完成断点续测；完成后一次点亮八维并写 baselineCompletedAt。
- **BR-V2-7 调优门禁**：评分/追问 prompt 变更必须通过回归集一致性门槛（阈值在 T28 立项时标定）才可上线；prompt 内容 Git 管理、版本状态 DB 管理、可一键回滚。
- **BR-V2-8 题库保障**：日常题每维度 ≥6 道（D35 上调：组包 5 道未练题 + 复测预留 1 道）；基线题每维度 2 道候选；题目难度主观标定初值，上线后用用户有效分数据校准。
- **BR-V2-9 计划生成规则（D35）**：主攻维度 = 画像最低分维度（同分按固定顺序）；目标分 = `min(100, 当前分 + 10)`；存在未知维度时不参与排序、本周计划暂缓生成并提示先完成基线测评。

## 6. 数据契约（V2 变更摘要，详表见架构蓝图 §3.3）

- **修改**：TrainingSession +sourceType/sourceId（会话来源）；Score +confidence；Question +domain。
- **新增**：training_plans（周计划）、training_packs + pack_items（训练包与包内题）、stage_records（阶段/复测记录）、prompt_versions + eval_runs（调优体系）；评测集以 YAML 文件 Git 管理。

## 7. MVP 原型设计说明（已确认的视觉方案）

用户于 2026-10-07 从三个概念原型（计划驱动 A / 战役地图 B / 画像联动 C）中按模块选定组合，组合版最终原型 [`v2-prototype-final.html`](v2-prototype-final.html) 为 V2 唯一视觉基准：

| 界面 | 采用形式 | 来源 |
|---|---|---|
| 首页 | 战役地图：横向关卡路径（起点✓→探索期✓→强化期·当前→复测期·锁定），周计划与训练包悬挂在当前阶段节点下 | 原型 B |
| 基线测评 | 起点关卡卡：断点续测横幅、12 格进度点（含琥珀加深题）、完成后八维点亮预览 | 原型 B |
| 周期训练计划 | 主攻卡（当前分→目标分+选择理由）+ 周一至周五排期三态 + 拒绝/撤销 + 周回顾 | 原型 C |
| 专项训练包 | 难度阶梯逐题解锁 + 可展开作答摘要与 AI 点评 + 包级诊断柱状图 | 原型 C |
| 成长阶段与复测 | 三阶段卡（含进入/离开条件）+ 复测触发卡 + 成长时间线 | 原型 C |
| 能力画像 | 8 维呈现 + 弱项「发起攻坚包」按钮 + 「一次仅一包」禁用态 | 原型 A |

统一规范：全部屏幕侧边栏常驻成长阶段标识；视觉语言沿用原型 B 色板（#2563EB / #F5F6F8 / 深色侧边栏 / 白卡微阴影 / 黑体栈）。

**已裁定事项（2026-10-07，D35）**：V1 的 3D 能力网络图在 V2 画像页**移除**——画像页采用 A 形式（8 维行内 + 弱项发起入口）为唯一呈现。原架构蓝图风险 R1 关闭。

## 9. V2 核心验证指标

- 基线测评完成率（新用户首日完成八维测评的比例）与加深触发率分布
- 周计划接受率 / 拒绝率；计划维度题完成占比
- 训练包完成率与放弃率；包级诊断的感知问卷评分
- 复测通过率（验证「真提升」占比）
- 训练方向有效性感知（延续 V1 指标）：「这次反馈是否让我更清楚自己的问题」1~5 分

# T14：测试库与开发库隔离

| 项目 | 内容 |
|---|---|
| 状态 | IN_PROGRESS（已派发 K2.8 子代理） |
| 依赖 | 无（基础设施任务） |
| 背景 | 集成测试与开发共用 docker PG 的 `skilltraining` 库：全量测试会在播种时归档真题、上架测试种子题且不恢复，曾导致产品预览异常（新用户抽到测试题）。2026-10-03 产品负责人批准立项 |

## 目标

全部测试运行于独立数据库 `skilltraining_test`；任意次全量测试后，开发库（`skilltraining`）数据零变化。

## 范围外

测试本身的用例改造（现有播种/清理逻辑保持不变，只是换库）；CI 流水线搭建。

## 方案（主代理设计）

1. 在现有 docker PG 实例内新建独立库 `skilltraining_test`（不新增容器、不改 docker-compose 端口）。
2. `.env` 与 `.env.example` 增加 `TEST_DATABASE_URL`（指向 5433 的 skilltraining_test）。
3. `vitest.setup.ts`：加载 `.env` 后，将 `process.env.DATABASE_URL` 指到 `TEST_DATABASE_URL`（必须早于任何 PrismaClient 实例化）。
4. 测试库准备脚本（`scripts/prepare-test-db.ts`，npm `pretest` 钩子自动执行）：库不存在则创建 → 对其执行 `prisma migrate deploy`（幂等，可重复运行）。
5. `README.md` 更新本地开发与测试说明。

## 受影响文件

`vitest.setup.ts`、`package.json`（scripts）、`scripts/prepare-test-db.ts`（新增）、`.env`（仅追加）、`.env.example`、`README.md`。

## 验收条件与完成证据

- `npm run test` 全量通过（当前基线 555 个）
- **隔离验证**：记录全量测试前后开发库 `questions` 表 status 分布快照，两者完全一致（真题不再被归档、种子题不再出现在开发库）
- `pretest` 脚本重复执行幂等
- 完成证据：测试输出、前后快照对照、脚本输出

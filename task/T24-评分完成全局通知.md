# T24 评分完成全局通知（Notification）

状态：IN_PROGRESS（2026-10-07 立项，决策见 Prd.md D26——4 项关键决策已经产品负责人逐项确认）

## 目标

评分是异步的（真实延迟 30~60 秒），当前用户离开等待页后只能靠自己记得到训练历史翻结果，链路长、易遗忘。本任务交付全局「通知提醒框」：评分完成后在**任意页面**右上角弹出常驻通知卡 +「叮」提示音，点击跳转该会话的评分结果页（/today/feedback/[id]）；用户关闭浏览器错过时，下次打开补弹一次。

## 范围外

- 通知中心/历史通知列表（V2 议题；错过的通知靠训练历史兜底）；
- 提示音开关（D26②：V1 默认开启无开关）；
- WebSocket/SSE 实时推送（D26⑤：复用轮询）；
- 多浏览器/多设备去重（localStorage 按浏览器隔离，V1 接受重复弹）；
- 基线测评会话的通知（D26⑦：基线有自己的完成体验，接口层直接排除）。

## 事实来源与前置依赖

- 决策全文：Prd.md D26（弹窗常驻、提示音、在反馈页不弹、补弹一次、轮询感知、失败兜底、排除基线——共 7 条）；
- 评分状态机：`prisma/schema.prisma` SessionStatus（reading/answering/followup/scored），`scoredAt`、`finalSubmittedAt` 字段；终答提交后评分完成前 status 仍为 followup；
- 懒触发评分：`app/api/training/[id]/feedback/route.ts`（未评分时后台触发 scoreSession 并立即返回 scoring；评分失败后用户再次进入反馈页会重触发——这是「评分遇到波动」通知的恢复通道）；
- 反馈页自身已有 scoring 轮询：`app/today/feedback/[id]/feedback-flow.tsx`（SCORING_POLL_INTERVAL_MS），D26③ 的「原地出分」能力已存在，本任务只做「该页面上不弹窗」的抑制；

- 客户端 API 适配层模式参考 `app/today/api.ts`；共享代码落点 `app/_shared/`（现有 nav-items.ts 先例）；

## 受影响模块/数据/接口

- 新增接口：`GET /api/training/score-notifications`——返回当前用户最近的可通知项：
  - `scored`：status=scored、scoredAt 在近 7 天内、非基线，按 scoredAt 倒序至多 5 条；
  - `stuck`：finalSubmittedAt 距今超 5 分钟、仍未 scored（status=followup）、非基线，按 finalSubmittedAt 倒序至多 3 条；
  - 统一返回 `{ items: [{ sessionId, caseTitle, kind: "scored"|"stuck", occurredAt }] }`（caseTitle 取与历史列表一致的案例名口径，参照 app/history 相关 view-model）；
- 新增前端模块：`app/_shared/score-notifier/`——
  - `view-model.ts` 纯函数：通知决策（去重键 `sessionId:kind`、首载 30 分钟静默规则、反馈页路径抑制、同屏至多 3 条排队、localStorage 上限 50 条 FIFO）；
  - `score-notifier.tsx` 客户端组件：挂载即轮询 + 每 10 秒一次，弹常驻通知卡（右上角 fixed，z 层级高于页面内容；「查看评分结果」主按钮 router.push 跳转 + 跳转后关闭，× 仅关闭），新通知出现时 Web Audio 合成两音「叮」（try/catch 容错，播放失败不影响弹窗）；
  - `api.ts` 适配层（失败/401 静默返回空）；
- 改动既有文件：仅 `app/layout.tsx` 挂载 `<ScoreNotifier />`（server 组件挂 client 组件，登录页 401 静默）；
- 无 schema 变更、无迁移。

## 失败与回滚

- 全部为新增模块，layout.tsx 仅一行挂载——摘除挂载即整体回滚；
- 接口异常/网络失败时前端静默（下一次轮询再试），绝不因通知功能影响任何页面正常渲染（组件内全部 effect 兜底 catch）；
- localStorage 读写失败（隐私模式）降级为「仅本次会话内存去重」，不抛错。

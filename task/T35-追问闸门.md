# T35 追问闸门（首答后判定是否追问）

- 状态：DONE（2026-10-19 实现落地 db0250c；2026-10-20 人审校准两轮收官：R2 放水 0、误伤率 20% 经产品负责人裁定达标）
- 决策来源：D37（maps/changelog.md 决策记录）；BR-4、D6、D22（Prd.md §1.5）；T05/T19/T22 已实现追问机制

## 目标与范围

**目标**：首答后由同一次 AI 调用先判定「值不值得追问」——不值得则走既有零追问通道直进终答，值得则给出现状的 1~2 问（D6 上限不变）。好答案不再被强制追问打扰。

**范围外（明确不做）**：

- 全动态 1~3 轮多轮对话（状态机轮次、前端多轮气泡、D6 上限修订）——属第二步，待闸门数据后另行立项设计；
- 系数规则（BR-2）与「追问不扣分」（BR-4）不变；
- 前端作答区改动（现状一框答 1~2 问与零追问跳过通道均不动）。

## 前置依赖

- 用户试测完成（试测数据用于校准判定阈值与验证体验收益）；
- 评分器人审校准管线（`scripts/eval-baseline-samples.ts` + `content/eval/baseline-8-human-review.json`，R2/R3 已交付）——判定质量需同等人审校准；
- 既有事实：`server/ai/followup.ts`（单次调用产 1~2 问 + 预生成提示，json_object 输出）；`server/modules/training/service.ts`（追问失败置空可跳过直达终答——零追问通道已存在）。

## 受影响模块、数据和接口

- `server/ai/followup.ts`：输出契约扩展为「是否追问 + 判定理由 + 追问列表（可为空）」；判定标准锚定主测维度 Rubric（主测无重大缺项、证据链完整 → 不追问）；
- `server/modules/training/service.ts`：追问落库分支处理（空列表 = 直进终答，复用现有跳过路径）；判定理由落库可审计（followups jsonb 扩展字段）；
- 评分输入不受影响（followupQuestions 为空数组的情形评分器已支持）；
- 前端：`app/training/session/training-flow.tsx` 仅在文案层处理「总监认为首答已足够，可直接终答」的零追问呈现（现状对空追问的兜底若有则可复用，需先核查）。

## 可执行步骤及顺序

1. 试测复盘：统计试测 8 题中「追问无增量价值」的比例与体感点（产出判定阈值输入）；
2. followup 生成 prompt 改造：先判定后生成，判定标准写死锚定主测维度；输出契约与解析改造（先 RED：followup 测试更新）；
3. service 落库分支：空追问走跳过通道；判定理由随 followups 落库；
4. 前端零追问文案核查与补齐；
5. 人审校准：构造「该追问 / 不该追问」样本集（可由 31 份既有样本的首答改造），人审盲评 vs 闸门判定，达标线参照 R3（排序无反转、误判率人审裁定）；
6. 门禁三件套 + 实测（好答案直进终答、缺项答案收到追问各一例）。

交付记录（2026-10-19）：①闸门实现全量落地（步骤 2~4、6 门禁部分）——followup.ts 先判定后生成、gate 标记落库、前端三态、retry 409 守卫，913 测试全绿；②同日追加「判定记录两分支落库 + 探针」——followups jsonb 首元素恒为 gate_decision 标记（含 shouldFollowup 与判定理由，存量 gate_skip 读取侧兼容），AI 客户端透传 reasoning_content，新增探针脚本 `scripts/gate-probe.ts`（--recent 判定分布监测，单一判定警示形同虚设；--live 真实调 DeepSeek 核查思考链，产生少量 token 消耗）；步骤 5（人审校准）与步骤 6 的实测部分仍未完成。

## 失败、回滚和数据保护

- 判定错误方向风险：放水（平庸答案逃过压力测试）比过严更危险——prompt 中判定标准从紧表述，校准时以人审为准调整；
- 回滚 = 恢复固定 1~2 问的 prompt 与解析（单文件回退），无数据迁移；存量会话 followups 结构向前兼容（新字段可缺省）。

## 测试、验收条件和完成证据

- 单测：生成解析（追问/零追问/ malformed 输出）、service 落库分支；集成：首答 → 零追问直进终答链路；
- 人审校准报告（判定一致率与误判方向分析，参照 `docs/v2/calibration-report-baseline-8-r3.md` 格式）；
- 实测记录：好答案与缺项答案各走通一次（截图或日志）；
- `maps/features.md` F1 训练闭环与 changelog 决策记录 D37 状态同步。

## 完成证据（2026-10-20 回填）

- **实现**：闸门 prompt（先判定后生成）+ 输出契约、gate_decision 判定记录两分支落库（reason 仅审计不下发）、前端三态（追问气泡/正向零追问卡/失败重试）、followup-retry 对闸门跳过 409、探针 `scripts/gate-probe.ts`（--recent 分布监测 / --live 思考链核查）；957 测试全绿。
- **阈值初校（探针实测）**：初版「任何疑义一律追问」过严（人审 high 样本全被判追问、形同虚设报警），调整为「结构性缺陷三类」标准后强弱样本区分正确。
- **人审校准（正式）**：31 份样本 × 产品负责人盲评（三值：该追问/不该追问/灰区，`content/eval/gate-human-review.json`）：
  - R1（结构性缺陷初版）：一致率 84.6%，放水 3（14.3%，未达标）——三份放水共性为「证据-结论错配」（有证据但证据证明不了结论），误伤 1（承认未知型被误判缺陷）；
  - prompt 调整：缺陷②扩展「证据-结论错配」+ 新增「承认未知保护」；
  - R2：一致率 96.2%，**放水 0（达标）**，误伤 1（B3-S3，可辩护的严格）；产品负责人裁定误伤率阈值 ≤20%（选 A），T35 收官；
  - 报告：`docs/v2/gate-calibration-report.md`（R2 定稿）+ `-r1.md`（对照留档）；管线：`scripts/eval-gate-samples.ts`（live 跑批 / 盲评材料生成 / 对照三模式，--cache 断点续跑）。
- 闸门判定质量达标线自此成为 D31 调优体系的回归门槛之一（后续 prompt/模型变更须复跑本管线验证放水=0）。

# T28 总监 Agent 可度量调优体系（F3）

状态：DONE（2026-11-03 产品负责人接受已知限制，完成本轮开发验收；评分与 V10 原自动门槛均未通过，V10 未启用。决策见 maps/changelog.md D31、D41~D43、D46 及验收时间线；需求与规则 docs/v2/prd-v2.md §4 F3、§5 BR-V2-7；架构蓝图 docs/v2/architecture-v2.md §2.6 / §3.2 / §3.3 / §4 R4·R6）

## 目标

建立总监 Agent 可度量调优体系，让评分/追问 prompt 的每次变更「可回归、可度量、可回滚」（BR-V2-7 调优门禁）：

1. **prompt 独立文件化 + 版本注册表**：评分/追问 prompt 从硬编码字符串抽离为独立文件（新建 `server/ai/prompts/`），Git 管内容、DB 管版本状态（draft/passed/active/rolled_back），可查询、可一键回滚；
2. **评测集契约**：每题 1~2 份标准参考答案 + 人工评分基准，YAML 文件 Git 管理（新建 `content/eval/`），在 `server/modules/scoring/calibration.ts`（现仅 3 例内置骨架）基础上扩展为文件加载；
3. **回归脚本**：扩展 `scripts/scoring-calibration.ts` 为完整回归——prompt 变更后对评测集逐例评分，与人工基准对比一致性指标，输出漂移报告并留档（eval_runs 表），未过门槛退出码 1；
4. **confidence 输出契约**：评分 prompt 增加 confidence（0~100）输出，解析并落库 Score.confidence（与 T27 协同：本任务负责 prompt 输出、解析与落库，T27 负责在基线加深判定中消费，BR-V2-6）；
5. **追问质量三查机制**：针对「是否针对用户答案程度 / 是否暴露真实盲点 / 是否泄露 Rubric 要点」三项检查——泄露检查规则化自动执行，其余先人工抽检，不追求自动化全量（D31）。

## 范围外

- 基线测评流程改造（归 T27；本任务只交付 confidence 的生产侧，加深判定消费侧不在本任务）；
- 评测集内容大批量生产（随 T33 题库批次同步产出，蓝图 §4 R4；本任务只建契约、工具链与首批样例）；
- prompt 内容本身的调优动作（体系建设完成后再持续进行；本任务 prompt 抽离以行为不变为准，唯一内容变更是新增 confidence 输出要求）；
- prompt 调优的 CI 自动触发（live 回归消耗 MiMo 额度，保持人工触发，同现有 scripts 惯例）。

7. 重构并确认 `npm run typecheck && npm run lint && npm run test` 全绿，新增可测代码覆盖率不低于 80%。

## 失败与回滚

- **迁移回滚**：prompt_versions / eval_runs 为全新表，回滚 = 反向迁移 drop 新表，不影响任何既有表与数据；Score.confidence 为可空列，回滚 = drop column，老数据本就为 NULL 无损；回滚前导出 eval_runs 报告留档（回归历史是调优资产，不随表删除而丢失——报告同时输出为文件）。
- **数据保护**：prompt 抽离以快照测试证明逐字不变，线上评分/追问链路在抽离前后行为一致；prompt 线上回滚 = DB 状态切换（active 指回上一 passed 版本），无需发版、无数据变更（蓝图 §4 选型）；content/eval/ 的 YAML 变更一律走 Git 评审可 diff。
- **回归脚本安全**：live 模式只读评分调用，业务表零写入（仅 eval_runs / prompt_versions 两表）；MIMO_API_KEY 仅服务端环境变量，报告与日志不得打印密钥与完整 prompt 之外的敏感数据。
- **门槛误阻断**：门槛全部可配置且标定方法留档；误阻断时经用户确认后调整门槛并在 eval_runs 报告注明调整理由，禁止静默放宽。
- **confidence 降级**：解析失败落 NULL 不阻断评分主流程；T27 消费侧按「NULL = 无置信度信息」处理（不触发加深判定），该口径在本任务完成证据中写明并同步 T27。

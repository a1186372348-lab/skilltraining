## 目标

案例背景从"AI 撰写的描述"升级为"逐字段可核验的事实"：数据契约强制每字段带引用，页面展示上标引用标记与来源列表。

## 范围外

参考资料（materials）本身的改动；评分 Rubric 的引用化（Rubric 是评分内部契约，不展示）。

## 新数据契约（题目 YAML）

```yaml
case_background:
  product:  { text: "……", citations: [1, 3] }
  audience: { text: "……", citations: [1] }
  scenario: { text: "……", citations: [2] }
  features: { text: "……", citations: [1, 2] }
  status:   { text: "……", citations: [4] }
case_sources:
  - id: 1                 # 从 1 开始连续编号
    title: "来源标题"
    publisher: "发布方（官方 / 媒体名）"
    url: "https://……"
```

校验强制（T02 schema 升级）：

- 五字段均为 `{text, citations}` 结构，text 非空、citations 非空；
- 每个引用 id 必须存在于 `case_sources`；`case_sources` 的 id 从 1 开始连续；
- url 必须为合法 http(s) 链接。

## 来源政策（写入 Prd.md D18 / BR-8）

优先级：① 官方一手来源（官网、官方博客、文档、财报、创始人公开发言）② 权威媒体深度报道 ③ 其他（publisher 如实标注）。**无法找到前两类来源的论断：改写为可引用的事实，或移出 case_background**（可保留到 `uncertainty` 内部备注字段，不在界面展示）。

## 受影响模块/数据/接口

- `server/modules/content/`：schema 升级（上述强制规则）与测试 fixtures 更新；
- `server/modules/training/today-view.ts`：case_background / case_sources 序列化（沿用 FR-10 出口防线）；
- `app/today/`（P3 案例卡）：五字段文本末尾**内联**引用链接——单引用显示「原文」，多引用显示「原文1」「原文2」……（小号蓝色、新标签打开、悬停提示「来源标题 · 发布方」）；**不设立独立来源列表区域**（2026-10-03 产品负责人修正）；
- `app/history/[id]/`（详情案例区）：同样的内联「原文」链接，不设独立来源区域；
- `content/questions/draft/Q01~Q12`：12 题 case_background 改写为新结构，逐字段配真实来源，解决既有 uncertainty 标注。

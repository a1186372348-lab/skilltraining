# T32 V1 小缺口修补（F2）

状态：PENDING（2026-10-08 立项，V2 功能包 F2 / 排期 P0，范围与排期决策见 maps/changelog.md D29）

## 目标

修补 V1 遗留的四个已知小缺口，打通「首次使用 2~3 分钟画像后立即训练」的核心路径断点：

1. **新用户首登引导**：首次登录（初始画像未完成）后自动引导至 `/onboarding`，不再让用户自己找入口；
2. **基线会话进历史**：基线测评产生的会话在训练历史列表中完整显示（带「基线」标识），当前经 `question.kind="daily"` 过滤被整体排除；
3. **画像页「下一步方向」动态化**：`server/modules/profile/ability-page.ts` 的 `nextFocusOf` 当前是固定规则文案占位（模块注释自标「T11 接入点」，T11 已 DONE），改为基于真实弱项（最低分维度 + 提示依赖）的动态结论，文案具体可行动（BR-7）；
4. **评分置信度展示**：在反馈页 / 画像页合适位置展示评分置信度——依赖 T28 的 `Score.confidence` 输出落地；T28 未完成时本项随 T28 之后单独交付，**不阻塞前三项**。

## 范围外

- V2 新功能（F1 题库扩容、F3 调优体系、F7 基线升级、F5/F4/F6 结构化训练——归 T27~T31 及其余 V2 任务包）；
- 画像页弱项「发起攻坚包」入口（归 T30，蓝图 §3.1 同一文件的另一处改动，本任务不做）；
- 任何 V1 闭环逻辑重构（选题引擎、评分状态机、通知机制等均不动）；
- 评分完成通知对基线会话的排除口径（D26⑦ 保持：基线不进通知，仅进历史列表）；
- 成长阶段产品化（探索期/强化期判定上屏归 T31；本任务仅复用其 V1 已有语义做文案分支）。

## 失败与回滚

- 第 1~3 项全部为既有文件的窄范围改动、无迁移：回滚 = 还原 verify 路由固定跳 `/`、hub-view 历史查询恢复 `kind: "daily"` 过滤、`nextFocusOf` 恢复占位文案；各项独立可拆，互不回滚牵连；
- 数据保护：本任务不写任何业务数据（首登引导只读 UserProfile 存在性；历史与画像页为查询/视图层）；不得借本任务回填或修改既有会话、分数、画像数据；
- 第 4 项依赖的 `Score.confidence` 迁移属 T28 范围：新增可空列，`prisma migrate` 反向迁移即安全回滚（老数据本为 NULL，无数据损失）；本任务消费侧回滚 = 摘除展示位渲染；
- 首登引导误判定风险兜底：判定只依赖 UserProfile 存在性，查询失败时按「有画像」处理（落首页、不引导），宁可不引导不得把老用户错送进 `/onboarding`。

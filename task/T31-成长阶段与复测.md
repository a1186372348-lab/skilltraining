# T31 成长阶段与复测（Stage & Retest）

状态：PENDING（功能包 F6，排期 P3 第 3 个；立项决策见 maps/changelog.md D29~D34）

## 目标

把「探索期 → 强化期 → 复测期」三阶段从选题引擎的内部逻辑升级为产品化、用户可见的成长主线：

- 阶段判定产品化：存在未知维度 = 探索期；画像完整 = 强化期；某维度连续 3 次有效分 ≥75 触发该维度复测（复测为**维度级状态**，不影响其他维度正常训练，BR-V2-4 / D33）。
- 复测规则落地（BR-V2-5 / D33）：换题不换维度（同维度、排除已练题）；复测题不占每日一题槽位；复测有效分 ≥60 通过（维度标记已验证、回到强化期），<60 判定为题型熟悉假象、该维度重回主攻候选。
- 复测启用前提（BR-V2-5 / 蓝图 R3）：该维度可用未练题 ≥1 道；不足时复测挂起并在 UI 提示，不阻塞日常选题。
- 可见性（D34）：侧边栏常驻成长阶段标识（全页面生效）+ 独立阶段页（三阶段卡含进入/离开条件、复测触发卡、成长时间线，视觉参照 docs/v2/v2-prototype-final.html 屏 5）。

## 范围外

- 专项训练包（T30）与周期训练计划（T29）本体；本任务只在选题优先级链中插入「待复测维度」层并定义与包/计划层的组合顺序（BR-V2-1 / D32：包 > 计划 > 复测 > 自适应）。
- 能力分数模型升级（近期权重/难度权重/衰减，V3 存档项，prd-v2.md §4）。
- 3D 网络图去留（蓝图风险 R1，在 T30 开工前裁定，本任务不触碰画像页 3D 图）。
- 题库生产与每维度 ≥4 道保障（T33 / BR-V2-8）；本任务只消费题量并处理不足时的挂起。
- 首页战役地图本体（随 T29/T30 交付）；本任务仅做复测期节点解锁条件文案与 stages 实时状态的联动。

## 受影响模块/数据/接口

- **Prisma 新表 `stage_records`**（蓝图 §3.3 草案字段）：`id, userId, dimension, type(retest_trigger/retest_pass/retest_fail), sessionId 可空（pass/fail 关联复测会话）, createdAt`；加 `@@index([userId, dimension, createdAt])`。维度状态为**派生态**：该维度最新一条记录决定状态（trigger 未决 = 待复测；pass = 已验证；fail = 重回主攻候选）；挂起不新增记录类型，由「trigger 未决且当前可用未练题 = 0」派生。
- **新增 `server/modules/stages/` 五件套**（模块形态参照 server/modules/auth/）：
  - `judge.ts` 纯函数：近 3 次有效分连续 ≥75 判定、阶段判定（探索/强化/复测）、复测通过线判定；判定口径——按 scoredAt 升序取该维度有效分序列，**只统计 sourceType ∈ {daily, extra, plan, pack} 的会话**（排除 baseline 与 retest 自身，防止复测高分连锁再触发）。
  - `service.ts`：`checkRetestTrigger(userId, dimension)`（评分钩子调用，幂等——已有未决 trigger 不重复插入）、`resolveRetest(...)`（复测评分后落 pass/fail）、`getStageOverview(userId)`（侧边栏 + 阶段页 + 首页联动的单一事实源）、挂起检查。
  - `repository.ts`（stage_records 读写 + 近 3 次有效分查询）、`schemas.ts`、`errors.ts`、`index.ts`。
- **修改 `server/modules/scoring/service.ts`**：scoreSession 落库完成后按得分维度逐个调用 stages 钩子；钩子必须 try/catch 兜底——stages 异常不得阻断评分主流程与 T24 通知链路；readExistingResult 短路路径天然不触发钩子（幂等第一层）。
- **修改 `server/modules/selection/service.ts`**（engine.ts 不动）：选题入口插入「待复测维度」层，位于计划层之后、现有引擎之前；命中时产出该维度未练题（排除已练，含加练历史）+ 固定理由文案模板（BR-V2-1 来源标注「复测验证」）；未决 trigger 但题量不足时该层 miss 落自适应，并向上返回挂起标记供 UI 提示。
- **修改 `server/modules/training/service.ts`**：新增 getOrCreateRetestSession（复用 extra 通道：isExtra=true、question.kind="daily"、sourceType="retest"、sourceId=trigger 记录 id；同 trigger 幂等——已有进行中复测会话返回同一个）。
- **新增接口**（统一 `server/lib/api-response.ts` 封装，未登录 401，非 AI 端点不接 aiEndpointRateLimiter）：
  - `GET /api/stages/overview`：当前阶段、各维度复测状态（含挂起与原因）、距下次触发的进度（各维度最近连续 ≥75 计数）、成长时间线（stage_records 倒序）；
  - `POST /api/stages/retest/start`：对指定待复测维度创建/取回复测会话（原型屏 5「现在开始复测」按钮）。
- **前端**：
  - 新增共享组件 `app/_shared/stage-badge/`（阶段标识 + view-model 纯函数），逐 shell 挂载：首页 home-shell、训练大厅 shell、画像 shell、我的/设置、阶段页，窄屏降级位置与各 shell 现有模式一致；
  - 新增阶段页 `app/stages/`（page + view-model + api 适配层）：三阶段卡（各含进入/离开条件）、复测触发卡（两结局说明，通过线文案 ≥60）、挂起提示卡、成长时间线；视觉参照原型屏 5，色板沿用原型 B；
  - 首页战役地图复测期节点：解锁条件文案改由 `/api/stages/overview` 实时驱动（含「已触发待复测/挂起」状态）；
  - 训练大厅/工作台：复测会话展示「复测验证」来源标识与理由文案。

## 失败与回滚

- **迁移回滚**：stage_records 为全新独立表、不被既有表外键引用——开发库回滚 = 手工 down SQL `DROP TABLE stage_records`（或 prisma migrate reset 重建），测试库由 pretest 钩子自动重建无需处理；既有表零改动、零回填，迁移失败不污染任何现有数据。
- **数据保护**：回滚代码（摘除钩子、selection 复测层、UI 挂载）后**不删除**已产生的 retest 会话及其 scores——它们 isExtra=true，按既有加练口径计入画像与历史，展示与统计不受影响；stage_records 表可整表丢弃，维度状态全部可从 scores 重算。
- **运行时兜底**：stages 钩子异常被 catch 并记日志，评分主流程、反馈页、T24 通知不受任何影响；`/api/stages/*` 异常时 stage-badge 降级为不渲染（catch 兜底），绝不因阶段功能影响任何页面正常渲染。
- **UI 回滚**：摘除各 shell 的 StageBadge 挂载与导航入口即整体回滚；阶段页路由可整体下线。

# T19：追问阶段提示（D22）

| 项目 | 内容 |
|---|---|
| 状态 | IN_PROGRESS（待派发 K2.8 子代理） |
| 依赖 | T05（AI 网关与训练会话）、T06（评分）、T17a（基线流程复用同一 TrainingFlow） |
| 事实来源 | `Prd.md` D22、BR-2（2026-10-05 修订）、BR-4、D7（范围澄清）；2026-10-05 产品负责人决策：追问阶段需要提示，且不接受点击后实时生成带来的二次延迟 |

## 目标

AI 追问阶段用户也能请求提示：生成追问的同一次 AI 调用为每条追问附带预生成一条提示并落库，用户点击时读库零等待；追问提示按半价（每次 −0.05）参与独立完成系数，与首答前提示共用 0.6 下限。

## 范围外

主问题 5 层提示树的任何改动（D5/D7 保持原样，首答后仍永久关闭）；追问轮次与追问生成质量调优；多条/分级追问提示（每条追问固定最多 1 条）；反馈页、画像页改动。

## 交付

1. **追问生成扩展**（`server/ai/followup.ts`，TDD 先行）：
   - prompt 扩展：要求模型对每条追问同时产出一条提示——提示是「思考支架」（引导方向、提示被忽略的因素类别），不得泄露 Rubric 要点与 forbidden_leaks，与追问同受既有防泄露硬约束；
   - 输出 schema 从 `{"followups": ["...", "..."]}` 改为带提示的结构（如 `{"followups": [{"question": "...", "hint": "..."}]}`），`parseFollowups` 同步升级为返回 `{question, hint}[]`；解析容错保持既有风格（截断到 2 条、容忍 ```json 包裹；hint 缺失/为空时降级为空串，不因此丢弃追问）；
   - `maxCompletionTokens` 现值 2048，产出变多后如实测截断可上调，注释说明原因。
2. **数据模型**（Prisma schema + migration）：
   - `TrainingSession.followups` jsonb 记录结构从 `{round, question}` 扩展为 `{round, question, hint}`；存量无 hint 的记录按无提示处理（读取侧容错，不做数据回填）；
   - `TrainingSession` 新增 `followupHintCount Int @default(0)`（追问阶段已释放提示次数，服务端记录为准）；
   - migration 只加列，默认 0，无破坏性变更。
3. **释放端点**（新增 `POST /api/training/[id]/followup-hint`，参照既有 hint 路由模式）：
   - 入参：`{ round: number }`（第几轮追问）；身份校验 + AI 端点限流（复用 `aiEndpointRateLimiter`）+ 会话归属校验；
   - 前置条件：会话处于 followup 状态（首答已提交）、该 round 存在且有预生成 hint、该 round 尚未释放过提示；
   - 幂等：同一 round 重复请求返回已释放的 hint，不重复计数；每轮追问最多释放 1 次；
   - 成功：对应 round 标记已释放 + `followupHintCount` 原子自增，返回 `{ round, hint, followupHintCount, coefficient }`（系数用修订后的 BR-2 公式重新计算）。
4. **系数公式修订**（`server/modules/training/coefficient.ts` + 测试）：
   - `independenceCoefficient(hintCount, followupHintCount = 0)`：`max(0.6, 1 − 0.1×hintCount − 0.05×followupHintCount)`；第二个参数缺省为 0，保持既有单参调用兼容；
   - 用整数运算避免浮点误差（沿用既有思路，如按 20 分制：`(20 − 2×n − m) / 20`）；
   - 所有调用点（today-view、training/service 首答/终答、scoring/service）传入 `session.followupHintCount`，评分四元组按新公式落库；
   - 边界测试：组合计数（如 hint=1 + followupHint=1 → 0.85）、共用 0.6 下限（如 hint=4 + followupHint=3 → 0.6）、缺省参数行为不变。
5. **会话视图契约**（`server/modules/training/today-view.ts` + `app/today/contract.ts`）：
   - followups 下发结构带 `round/question` 与「该轮是否可请求提示 / 是否已释放」（**未释放时绝不下发 hint 明文**，释放后下发）；
   - 新增 `followupHintCount` 下发；`coefficient` 按新公式计算。
6. **前端**（`app/today/training-flow.tsx` 追问区）：
   - 每条总监追问气泡下方/旁提供「◇ 给我一个提示」入口（未被释放且该轮有提示时显示）；点击调 followup-hint 端点，就地展开提示内容（读库响应，无长等待，但仍按既有 pendingAction 模式防连点）；
   - 已释放的追问提示随会话持久展示（刷新后仍在）；该轮无预生成提示（AI 降级/老数据）时不显示入口；
   - 追问区底部系数微文案同步：显示组合后的提示次数与当前系数（如「本题提示 1 次 · 追问提示 1 次 · 独立完成系数 ×0.85」），延续 D12 透明化原则；
   - 基线流程（/baseline）复用同一 TrainingFlow，自动获得该能力，不单独改动。
7. 全绿：`npm run typecheck && npm run test && npm run lint && npm run build`。

## 失败与回滚

- 追问 AI 调用失败：沿用既有降级（追问为空、直达终答），追问提示自然不存在，前端不显示入口；
- prompt 扩展导致追问质量回退：回滚点为 `server/ai/followup.ts` 单文件（schema/端点/系数公式向后兼容，无 hint 时行为与现状一致）；
- migration 仅新增可空/默认值列，回滚不破坏存量数据。

## 验收条件与完成证据

- 首答提交后，每条总监追问旁出现提示入口；点击后**立即**展开提示（无二次 AI 等待），系数微文案按 −0.05/次同步更新；
- 同一轮追问重复请求提示不重复计数（幂等）；刷新页面后已释放提示仍在；
- 未请求任何追问提示时，系数与现状完全一致（回归）；
- 评分落库四元组中的系数按新公式计算（含追问提示半价项）；
- 质量门禁四项全绿，新增/修订测试覆盖：parseFollowups 新结构解析、系数组合公式、followup-hint 端点（含幂等与越权/越状态拒绝）。

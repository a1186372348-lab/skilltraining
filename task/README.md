# 执行任务（task/）

> 文档类型：临时执行方案与可执行任务入口
> 负责范围：按阶段或功能拆分的可执行任务、临时执行方案、验收条件与完成证据
> 更新触发：任务状态变化、新任务立项、任务验收完成

## 目录职责

| 目录 | 负责内容 | 不负责内容 |
|---|---|---|
| `task/` | 当前要执行的任务、步骤、验收和完成证据 | 通用开发规范、方案全文、会话进度记录 |
| `maps/` | 已实现的当前事实 | 任务执行日志、阶段进度 |
| `docs/` | 计划方案、评审材料 | 可执行任务正文 |

## 内容准入

每个任务文件至少包含：

- 明确目标和范围外内容
- 事实来源与前置依赖（引用 `maps/`、`docs/` 或 `Prd.md`，不复制全文）
- 受影响模块、数据和接口
- 可执行步骤及顺序
- 失败、回滚和数据保护要求
- 测试、验收条件和完成证据

## 状态约定

- 状态枚举：`PENDING` / `IN_PROGRESS` / `DONE` / `BLOCKED` / `REMOVED_BY_USER`。
- `DONE` 必须附完成证据（测试通过记录、验证命令输出摘要或交付物路径）。
- 修改任务目标、验收条件或完成状态必须取得用户明确确认；范围删除一律使用 `REMOVED_BY_USER` 并记录理由。

## 读取规则

1. 选定任务后完整读取该任务文件，并按其引用核对 `maps/` 事实与 `docs/` 方案。
2. 引用的地图或方案仍按各自渐进读取规则只读相关章节。
3. 执行期间若任务与当前代码事实冲突，立即停止并在方案层解决，不擅自推进。

## 会话边界

- `task/` 只保存任务契约、正式状态、最终完成证据和工件引用。
- 不得在任务正文追加当前进度、执行流水、代理留言或会话摘要。

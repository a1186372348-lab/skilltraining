# T38 训练终止与重启

- 状态：DONE（50e876e；2026-10-20 产品负责人实测确认「修改没有问题」）
- 决策来源：D40（maps/changelog.md 决策记录）
- 背景：用户开始训练后无法退出当天题目，只能点击「继续训练」被迫完成（产品负责人试测后反馈）。

## 目标与范围

**目标**：为训练增加终止能力——「当前训练」卡进行中态新增「重启训练」按钮，二次确认后终止当前会话、卡片回到未开始态；终止的会话以 `abandoned` 状态保留（历史可见、不评分不计入画像）；重启后换新题。

**范围外（明确不做）**：

- 基线会话的终止（基线题必须完成，D19 门禁不变；服务端拒绝）；
- 已提交终答待评分会话的终止（评分已在路上，无终止意义；服务端拒绝）；
- 工作台页内的终止入口（V1 只出卡片入口）；
- 历史详情页对 abandoned 会话的重做（只读展示即可）。

## 前置依赖（既有事实）

- 会话状态机：`TrainingSessionState`（reading/answering/followup/scored）+ `nextState` 单一事实源（`server/modules/training/`）；
- 当前训练卡：`app/training/current-training-card.tsx`（D28 首页/大厅同源），数据源 `server/modules/training/hub-view.ts` 的 `getCurrentTrainingCard`（in_progress 查询 `state: { not: "scored" }`）；
- 今日会话选择：`getLatestDailySession` / `getOrCreateTodaySession`（today 路由，T21）；选题排除：`pickQuestion`（T11，排除练过题与近期同产品案例）；
- 限流模式：`aiEndpointRateLimiter`（参照 extra 路由）。

## 受影响模块、数据和接口

1. **Schema**：`TrainingSessionState` 新增 `abandoned`（Prisma 枚举 + 迁移文件；测试库 pretest 自动 deploy）。
2. **状态机**：`nextState` 新增 ABANDON 事件（reading/answering/followup → abandoned；scored 终态不可转）。
3. **终止接口**：`POST /api/training/[id]/abandon`——守卫：会话归属、question.kind=daily（基线 409）、state ∈ {reading, answering, followup} 且 finalSubmittedAt 为 null（已提交终答 409）；幂等（已 abandoned 返回成功）；统一限流；无 AI 调用。
4. **数据口径**：`getCurrentTrainingCard` 的 in_progress 查询排除 abandoned（state notIn [scored, abandoned]）；`getLatestDailySession` 与 `getOrCreateTodaySession` 的复用查询排除 abandoned；`pickQuestion` 排除含 abandoned 会话的题目（先核实现有排除语义，按「被终止当日不再选到」补齐）。
5. **工作台直达守卫**：`GET /api/training/[id]` 对 abandoned 会话返回 409（新错误码如 `SESSION_ABANDONED`），前端重定向训练大厅。
6. **前端卡片**：InProgressCard 在「继续训练」右侧加「重启训练」（次级样式）；两步内联确认（点击 → 「丢弃当前作答并重启？」确认/取消）→ POST abandon → 卡片刷新回 not_started（与父级数据流对齐，选最干净的刷新方式：父组件是客户端取数则加刷新回调，服务端组件则 router.refresh()）。
7. **训练历史**：abandoned 会话在历史列表以「已终止」徽章展示（HubHistoryItem 已有 state 字段，前端按 state 渲染）；确认历史查询不把 abandoned 误显示为进行中。
8. **文档同步（DoD）**：`maps/features.md` F1 训练闭环（终止与重启规则）；`maps/architecture.md`（会话状态机新增 abandoned）；changelog 时间线随合并补记。

## 失败、回滚和数据保护

- 终止是状态推进而非删除，数据零损失；回滚 = git revert + 迁移回滚（V1 开发库可接受）。
- 并发双击：守卫条件 updateMany 保证只有首次生效（与既有终答幂等同款模式）。
- 终止不影响评分中会话（finalSubmittedAt 为 null 才允许），不会出现评分落库到终止会话的竞态。

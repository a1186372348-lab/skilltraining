# T17a：能力基线测评流程（D19 / BR-9）

| 项目 | 内容 |
|---|---|
| 状态 | IN_PROGRESS（已派发 K2.8 子代理） |
| 依赖 | T05（训练闭环）、T06（评分画像）；基线题内容由 T17b 并行生产 |
| 事实来源 | `Prd.md` D19、BR-9、1.3 第 2 项（2026-10-04 产品负责人决策） |

## 目标

新用户注册后第一个接触的是能力基线测评：2 道综合题（合计覆盖 8 维）按固定顺序依次完成，系统建立初始能力边界后才解锁日常训练。

## 范围外

基线题内容生产（T17b）；主动重测（V2）；基线专属评分模型（复用现有评分）。

## 交付

1. 数据与契约：`questions` 增加 `kind`（baseline/daily，默认 daily）字段（Prisma 迁移）；`user_profiles` 增加 `baseline_completed_at`（可空时间戳）；题库 YAML schema 与导入同步支持 `kind`。
2. 基线服务（`server/modules/baseline/` 或并入 training 并显式分区）：`getBaselineStatus(userId)` → { required, total: 2, doneCount, nextQuestion }（按题 id 固定顺序取 kind=baseline 且 published 的题，以用户已评分的基线会话计数）；全部评完 → 写 `baseline_completed_at`。
3. 基线会话复用训练闭环：会话创建指向基线题（today 系列接口在基线未完成时返回基线会话；追问/提示/评分规则完全一致，独立完成系数同样适用）。
4. 门禁逻辑：基线未完成时——`GET /api/training/today` 与首页今日任务卡指向 `/baseline`；选题引擎的日常题池排除 kind=baseline 题。
5. `/baseline` 页面（复用侧边栏与 TrainingFlow）：开场说明卡（这是一次能力边界测绘，2 道综合题，约 20~30 分钟，中途退出可恢复）、进度指示（第 1/2、2/2 题）、最后一题评分完成 → 跳转 `/profile`（能力边界首次揭晓）→ 首页。
6. TDD：门禁分支（未完成/完成 1 题/全部完成）、完成标记幂等、日常题池排除、会话复用正确性。

## 失败与回滚

基线中途退出可恢复（会话状态机既有能力）；迁移为纯增量，回滚即删列。

## 验收条件与完成证据

- 新用户：登录 → 画像 → 强制进入基线（今日训练不可达日常题）；两题依序完成后自动标记并解锁日常训练
- 老用户（已完成基线）：流程不受影响
- `npm run typecheck && npm run test && npm run lint && npm run build` 全绿；migration 对空库与现库均成功

# T21 加练链路（「再练一题」真正出新题）

状态：IN_PROGRESS（2026-10-07 立项，产品负责人确认开工）

## 目标

打通 Prd.md「每日一题 + 可加练」（D3：加练同等计入画像）的缺失链路：用户点击「再练一题」时真正创建一道新题的加练会话并进入作答，而不是回到已完成的每日一题。

根因（2026-10-07 产品负责人走查发现）：反馈页与首页仪表盘的「再练一题」均只是指向 /today 的纯链接；GET /api/training/today 只按 `{userId, date, isExtra:false}` 复用每日会话，全库无任何创建加练会话的入口。地基已就绪：选题引擎（T11 `selectTodayQuestion`，每日一题与加练共用，排除全部练过题 + 近期同产品案例）与 `TrainingSession.isExtra` 字段。

## 范围外

- 加练次数硬上限（V1 验证期不设，仅接口级统一限流兜底；后续按 R5 预算监控再议）；
- 训练页「加练中」标识（题目本身即最强信号，历史列表已有「加练」徽标）；
- 选题引擎策略调整、画像计入规则调整（D3 既定不变）；
- 基线测评流程（isExtra=true 但 question.kind=baseline，本任务不得影响其会话选择）。

## 事实来源与前置依赖

- Prd.md D3（加练同等计入画像）、D19（baseline 题不参与日常选题）、D24（本任务决议）、核心链路「每日一题 + 可加练」；
- `server/modules/selection/service.ts`：`selectTodayQuestion(db, userId)` 加练可直接复用（调用方负责会话落库）；
- `server/modules/training/service.ts`：`getOrCreateTodaySession` 现有每日幂等复用模式；
- `server/modules/baseline/service.ts`：基线会话以 isExtra=true 落库但 question.kind=baseline——加练查询必须按 `question.kind="daily"` 过滤，避免混淆；
- `prisma/schema.prisma`：`Question.kind`（daily/baseline）、`TrainingSession.isExtra/date/finalAnswer/startedAt`。

## 受影响模块/数据/接口

- 新增：`POST /api/training/extra`（创建/复用加练会话，返回 `{ sessionId }`；鉴权与限流模式与既有训练端点一致）；
- 修改：`server/modules/training/service.ts`（新增 `getOrCreateExtraSession` 与「当天最近非基线会话」查询）；`GET /api/training/today`（会话选择优先级）；
- 前端三处接线：`app/today/api.ts` 新增 `startExtraSession`；`app/today/training-flow.tsx` DoneSection 新增「再练一题」按钮；`app/today/feedback/[id]/feedback-flow.tsx` 与 `app/_dashboard/home-dashboard.tsx` 的「再练一题」由纯链接改为调接口后跳转；
- 数据：无 schema 变更（复用 isExtra）；无迁移。

## 可执行步骤（TDD）

1. `getOrCreateExtraSession(db, userId)`：当天存在「未提交终答（finalAnswer=null）且 question.kind=daily」的会话 → 直接返回该会话（幂等复用，防连点）；否则经 `selectTodayQuestion` 选题并创建 `isExtra=true、date=今日、state=reading` 会话（并发兜底回读，参照每日会话模式）。先写 RED 测试：无会话新建 / daily 完成→建 extra / extra 进行中复用 / extra 终答后再建下一道 / 已练题不再被选中。
2. `GET /api/training/today` 会话选择改为「返回当天最近一个 question.kind=daily 的会话（startedAt 倒序）」：存在即返回（进行中自然优先——加练只在全部完成后才可创建，任意时刻至多一个进行中会话）；不存在走现有 `getOrCreateTodaySession` 创建 daily。基线门禁（kind=baseline）逻辑不变。补 RED 测试：进行中加练优先返回 / 全部完成返回最近会话 / 基线会话不被误返。
3. `POST /api/training/extra` 路由：参照既有训练端点的鉴权 + 统一限流 + `jsonOk/jsonError` 模式，返回 `{ sessionId }`；RED 测试：401 / 429 / 成功 / 复用返回同 id。
4. 前端三处接线（均为「调接口 → 成功后进入/刷新今日训练 → 失败行内提示」）：DoneSection 加按钮（成功后重新 load）；反馈页「再练一题」Link 改按钮（成功后 router.push /today）；仪表盘 CTA 同样接线（未完成态的原跳转行为不变）。
5. 全量门禁：`npm run typecheck && npm run lint && npm run test`。

## 失败与回滚

- 选题引擎失败：沿用其既有降级（顺序取未练题），加练链路不新增失败面；
- 接口失败前端行内提示，不影响已完成内容展示；
- 回滚点：training/service.ts、today/route.ts、新增 extra 路由、三处前端文件；数据零改动，已创建的加练会话与历史一致（isExtra 语义本就存在）。

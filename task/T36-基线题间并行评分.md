# T36 基线题间并行评分（作答不等评分）

- 状态：IN_PROGRESS
- 决策来源：D38（maps/changelog.md 决策记录）；D19 / BR-9（基线测评）；T17a 已实现基线流程
- 背景：8 题基线试测暴露——现状每题提交终答后，前端轮询等评分完成（35~49 秒）才加载下一题，8 题累计干等约 4~6 分钟。

## 目标与范围

**目标**：终答提交后立即进入下一题，评分在后台并行运行，用户全程无感等待。全程唯一等待收敛为最后一题提交后的「能力边界生成中」收尾页（约一次评分时长），并包装为揭晓仪式。

**范围外（明确不做）**：

- 日常训练的评分等待设计（反馈页 P4 懒触发轮询不变）；
- T35 追问闸门（题内逻辑，与本任务串行实施）；
- 评分 prompt / 评分器本身改动；
- 基线完成判定语义（全部评分完成才写 baseline_completed_at、才解锁日常训练）不变；
- 基线过程中不展示任何单题分数与反馈（现状设计保持）。

## 前置依赖（既有事实）

- `server/modules/baseline/service.ts`：`getBaselineStatus`（nextQuestion 现按「未评分」找、doneCount=已评分数、全部评完幂等写 baseline_completed_at）；`getOrCreateBaselineSession`（按 {userId, questionId} 幂等复用）。
- `server/modules/feedback/view.ts`：`triggerBackgroundScoring`（进程内 inflight 集合去重、失败仅日志不落库待重试、scoreSession 幂等）——现为反馈页私有。
- `app/api/training/[id]/final-answer/route.ts` + `server/modules/training/service.ts` 的 `submitFinalAnswer`（终答落库，幂等，状态保持 followup）。
- `app/api/training/baseline/route.ts`（基线状态端点）；`app/api/training/today/route.ts`（基线门禁：required && nextQuestion → 返回基线会话，否则落日常分支）。
- `app/baseline/baseline-flow.tsx`（轮询推进：现侦测终答 → triggerFeedback 等 ready → 才推进下一题）；`app/baseline/view-model.ts`（进度文案纯函数，均按 doneCount）；`app/baseline/api.ts`（triggerFeedback 将随改造下线）。
- `app/training/session/training-flow.tsx`（onSubmitFinal：redirectToFeedbackOnDone=false 时提交后留在原地，等 BaselineFlow 轮询推进）。
- `app/training/current-training-card.tsx`（onStartToday 调 today 接口，kind=baseline 时跳 /baseline）。

## 受影响模块、数据和接口

1. **评分触发共享化**：`triggerBackgroundScoring` 从 feedback/view.ts 抽为 `server/modules/scoring/trigger.ts`（inflight 去重、失败释放待重试语义不变；deps 可注入便于测试）；feedback/view.ts 改为调用它，既有行为不变。
2. **终答提交即触发评分**：final-answer 路由在 `submitFinalAnswer` 成功后后台触发评分（重复提交触发无害：scoreSession 幂等 + inflight 去重）；路由改工厂模式注入 deps（参照 feedback 路由 createFeedbackGetHandler）。
3. **`getBaselineStatus` 拆分两套计数**：
   - 新增 `answeredCount`（已提交终答的基线题数，驱动流程推进）；`doneCount`（已评分数）保留，完成判定与 baseline_completed_at 幂等写入不变；
   - `nextQuestion` 改为「按 id 升序第一道未提交终答的题」；
   - 边界：全部已作答但未全部评完 → required=true 且 nextQuestion=null（中途状态，不许落入日常训练）。
4. **GET /api/training/baseline**：响应加 `answeredCount`；读取状态后对「已提交终答且未评分」的基线会话补触发后台评分（失败自愈通道；该端点被收尾页低频轮询，inflight 去重保证不重复调 AI）。
5. **GET /api/training/today 门禁边界**：required=true 且 nextQuestion=null（全部作答待评分）时不得落入日常题分支——返回 409 BaselineError（新错误码 `BASELINE_SCORING_PENDING`）；前端各 today 调用方（current-training-card、training-flow、baseline-flow）据 code 重定向 /baseline（与既有 BASELINE_SESSION 同模式）。
6. **前端 `app/baseline/`**：
   - 轮询驱动改为基线状态：answeredCount 增加 → 推进 roundKey 加载下一题；answeredCount≥total → 进入 finishing 阶段继续轮询；required=false → 跳 /profile；
   - 立即推进：TrainingFlow 新增可选 `onFinalSubmitted` 回调（仅 redirectToFeedbackOnDone=false 时提交成功后调用），BaselineFlow 借此即时刷新推进，轮询作兜底；
   - 首屏与 intro 判定：today 接口返回 BASELINE_SCORING_PENDING → 直接进 finishing；`shouldShowIntro` 的计数参数改 answeredCount；
   - finishing 页重做：「能力边界生成中」+ 评分完成进度（doneCount/total，逐项点亮的仪式感）+ 说明文案；超过约 3 分钟追加「仍在努力生成」提示，不离开页面、继续轮询自愈（基线未完成，其他入口均会指回）；
   - 进度文案（progressText / baselineStageText / currentQuestionIndex）改按 answeredCount；删除「评分处理中，稍后自动进入下一步」提示与 baseline api.ts 的 triggerFeedback。
7. **TodayView.baselineProgress**：`{ done }` 改传 answeredCount（进度口径统一为已作答；前端无消费方，仅路由测试断言，同步更新）。

## 失败、回滚和数据保护

- 评分失败自愈：终答触发失败 → 状态查询补触发重试（inflight 去重防重复 AI 调用）；MiMo 超时高发时段收尾页最坏等待数分钟，文案管理预期。
- 门禁不能漏：全部作答未全部评分期间，任何 today 入口必须挡回 /baseline（画像数据未齐，自适应选题无依据）。
- 进程内 fire-and-forget 与 inflight 为 V1 单实例前提（与限流器同一约定，注释写明）。
- 回滚 = 还原 baseline-flow 轮询逻辑与服务端触发点；无数据迁移，finalSubmittedAt / scoredAt 语义未变，中途回滚数据安全。

## 试测修正（2026-10-14 试测暴露，已随本任务一并交付）

1. **加练接口缺基线门禁**：基线未完成用户可从反馈页「再练一题」进入日常加练会话（试测中真实发生，用户被带离基线流程）。修复：`app/api/training/extra` 增加基线状态检查，未完成返回 409 `BASELINE_REQUIRED`；三处「再练一题」前端入口（当前训练卡 / 工作台完成卡 / 反馈页）据 code 挡回 `/baseline`。
2. **基线题反馈页按钮上下文错误**：反馈页对基线题会话仍显示日常动作「再练一题」。修复：反馈视图下发 `questionKind`，基线题反馈页主按钮改为「回到基线测评」（Link 至 /baseline），不再出现加练入口；日常题反馈页不变。
3. **题间切换突兀**：提交终答后立刻切到下一题，缺少确认节拍（产品负责人试测体感反馈，经方案选择定为手动节奏）。修复：新增题间过渡卡——「本题已提交 ✓ + 分段进度条 + 评审统一揭晓预告 + 手动按钮继续」（最后一题按钮为「完成测评，查看能力边界 →」）；提交后同步切换避免完成卡闪烁，计数先乐观置值、状态刷新后校准。
